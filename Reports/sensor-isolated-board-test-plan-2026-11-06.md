# STM32H7 传感器、按键与板载屏独立测试方案

日期：2026-11-06  
状态：讨论结果汇总与实现设计，尚未实现、编译、烧录或完成板上验收。  
范围：`SmartCar/` 固件的独立板测入口；本报告位于仓库 `Reports/`，不替代后续须先行提交的功能规约与 docs 契约。

## 1. 目标与已确认决定

目标是在真实板卡上逐项观察传感器和按键，减少其他业务的干扰，便于核对接线、原始读数、响应方向和采集时序。

| 事项 | 最终决定 |
|---|---|
| 本轮范围 | 传感器、按键、板载屏；电机、风扇、Flash、通信业务、整车控制不作为本轮被测功能 |
| 测试选择 | 编译期宏选择一个测试；切换后重新编译、烧录，上电直接进入所选测试 |
| 函数组织 | 每个独立测试有一个上电入口函数；中断采集另设对应处理函数 |
| 采集上下文 | 传感器使用正式运行对应的中断、周期和优先级，不用低频前台轮询替代 |
| 按键例外 | PC13及两组ADC按键保留现有前台轮询方式，不迁入TIM6/TIM7 |
| 板载屏 | 固定顺序、主要显示数据，尽可能一屏放完，不增加翻页操作 |
| IMU显示 | 使用串口上传到VOFA+，测试期间不操作LCD |
| 串口协议 | JustFloat；测试模式460800波特率、8N1；每1ms样本完整上传 |
| IMU数据 | 陀螺与加速度分别测试；每帧X/Y/Z三轴原始码转float，不做零偏消除 |
| IMU驱动缺陷 | 用户最后决定“先不修了”；不修复本轮读取错误返回，不据此关闭既有问题 |
| 当前授权 | 汇总并生成报告；不修改固件代码或工程配置 |

最终决定覆盖前面讨论中已被替换的建议：不采用20ms前台传感器采集、不采用编译期分页或按键翻页、不采用IMU与LCD分片共用SPI4、不采用115200下的抽样上传、不将按键测试迁入定时中断。

## 2. 调度与依赖

| 测试对象 | 采集/处理位置 | 周期 | 频率 | 输出 |
|---|---|---:|---:|---|
| 四路电感，逐路独立测试 | TIM6 | 2ms | 500Hz | 板载屏 |
| 16路灰度完整帧 | TIM6 | 2ms | 500Hz | 板载屏 |
| DL1B测距轮询 | TIM6 | 2ms | 500Hz | 板载屏 |
| IMU三轴陀螺原始读取 | TIM15 | 1ms | 1kHz | VOFA+ |
| IMU三轴加速度原始读取 | TIM15 | 1ms | 1kHz | VOFA+ |
| 左轮、右轮编码器，分别测试 | TIM15 | 1ms | 1kHz | 板载屏 |
| 电池ADC采样与既有滤波 | TIM7 | 5ms | 200Hz | 板载屏 |
| PC13、KEY1、KEY2，分别测试 | 前台轮询 | 无新增固定周期 | 不宣称固定频率 | 板载屏 |
| LCD自身测试 | 前台 | 独立运行 | 不作为传感器采样时钟 | 板载屏 |

说明：

- ADC1继续按现有十rank连续DMA采集。表内频率是中断读取/处理频率，不是ADC底层转换频率；不改rank、分辨率、DMA存放位置和D-Cache约束。
- 电感单路测试每个TIM6拍读取指定通道最近值，不保证每个软件读取对应独立新转换。现有四路八读去极值处理不属于单路原始采集测试的通过结论。
- 灰度继续调用现有完整帧接口，保留选址、五个新转换丢前三均后二及700μs预算，不用连续读取DMA内存替代新转换机制。
- DL1B的500Hz是轮询调用频率，不表示每秒产生500个新距离。
- 编码器保持1ms读清；不得让前台显示或其他业务再次读取硬件计数器。
- IMU传感器名义ODR与TIM15读取频率不是同一概念；本轮不声称每次读取都由DRDY证明为独立新样本。
- 正式IMU角速度处理和角度积分位于TIM6的2ms链。本轮原始传感器测试不接入这条处理链，不把原始读数观察当成积分功能验收。
- 保持TIM15与TIM6既有优先级0；其余中断优先级保持对应工程配置，不通过提高优先级掩盖执行超期。

## 3. 启动隔离

测试分支应位于 `Core/Src/main.c` 的 `USER CODE SysInit` 内：保留HAL、系统时钟及现有PLL3/SPI45补丁，然后在正常整组 `MX_*` 初始化和 `App_Init()` 之前进入测试。

```text
HAL_Init / SystemClock_Config / PLL3配置
  └─ 测试选择宏非NONE
      └─ BoardTest_Run()
          ├─ 初始化当前测试所需外设
          ├─ 必需的MX初始化后恢复SPI45时钟选择
          ├─ 初始化显示端：LCD或测试串口
          └─ 所选独立测试入口（不返回）
              ├─ 初始化状态、快照或队列
              ├─ 清中断挂起状态并启动对应定时器
              └─ 前台显示/发送；中断采集
```

`BOARD_TEST_NONE` 才继续正常固件启动。非法测试编号应编译报错；测试函数意外返回也不得落入正常业务启动。

| 项目 | 测试模式处理 |
|---|---|
| 正常Lifecycle/Scheduler启动链 | 不执行 |
| 电机/风扇PWM | 不启动；不加载正常空闲风扇占空比 |
| 参数加载、日志、无线调参、SCB业务 | 不初始化、不运行 |
| TIM6/TIM7/TIM15 | 只启动所选测试必需项；不通过现有整体启动接口捆绑启用其他定时器 |
| 正常TIM15综合采样体 | 测试编译分支替换，只读取选中对象，不捆绑编码器、IMU与日志 |
| 无关外设IRQ | 不启用或在测试BSP中屏蔽，特别检查GPIO初始化带来的Wi-Fi EXTI |
| SysTick | 保留，供HAL时基与前台刷新节流使用 |
| IWDG | 本轮测试不主动启动，不调用正常辅助业务喂狗链 |

隔离仅表示软件执行路径独立。共用电源、ADC扫描以及物理模块仍可能造成电气影响；报告不把这些描述成已经完全隔离。LCD背光所需TIM1不属于被测电机PWM。

入口结构示意（省略正式文件和函数Doxygen；实施时须补齐）：

```c
void BoardTest_RunGray(void)
{
    BoardTest_InitGrayState();
    BSP_ADC_Init();
    BSP_Gray_Init();
    BSP_BoardTest_StartControlTimer();

    while (1)
    {
        BoardTest_ServiceDisplay();
    }

/* 由测试模式TIM6分派，每2ms调用一次；不从前台补调。 */
void BoardTest_GrayISR(void)

```

| 入口函数 | 读取/处理与必要依赖 | 人工操作和观察目标 |
|---|---|---|
| `BoardTest_RunLcd` | SPI4、TIM1背光；固定数字、负数、变化计数及五行边缘 | 检查方向、清晰度、截断、数字缩短后的残留 |
| `BoardTest_RunInductanceHL` | TIM6；`BSP_ADC_IND_H_L` | 固定高度和供电，改变与通电赛道相对位置，记录响应 |
| `BoardTest_RunInductanceVL` | TIM6；`BSP_ADC_IND_V_L` | 同上，核对竖左实际接线 |
| `BoardTest_RunInductanceVR` | TIM6；`BSP_ADC_IND_V_R` | 同上，核对竖右实际接线 |
| `BoardTest_RunInductanceHR` | TIM6；`BSP_ADC_IND_H_R` | 同上，核对横右实际接线 |
| `BoardTest_RunGray` | TIM6；ADC DMA、选择线、`BSP_Gray_ReadFrame` | 黑底/白线，固定高度和光照；逐路遮挡核对实际通道顺序 |
| `BoardTest_RunGyro` | TIM15；IMU、测试串口 | 静止观察波动；分别绕X/Y/Z转动，记录轴响应和符号 |
| `BoardTest_RunAccel` | TIM15；IMU、测试串口 | 改变静止姿态和翻转，记录重力在各轴的分量 |
| `BoardTest_RunDl1b` | TIM6；I2C2、XS；先Update再读缓存 | 用尺设置多个固定距离，记录当前有效性和无效次数 |
| `BoardTest_RunEncoderLeft` | TIM15；TIM5；只读清左轮 | 手动正反转；静止检查持续异常计数 |
| `BoardTest_RunEncoderRight` | TIM15；TIM3；只读清右轮 | 同上，右轮独立测试 |
| `BoardTest_RunBattery` | TIM7；ADC DMA；`Battery_Init/Update` | 固定供电，记录原始/滤波ADC与万用表电压 |
| `BoardTest_RunAdcKey1` | 前台；仅KEY1原始读数 | 逐个按键记录稳定区间、波动范围及松开值 |

同类测试可共用内部实现，但每项保持独立上电入口与固定被测通道。编码器现有初始化同时启动两轮，测试BSP须支持按轮初始化；现有运行接口不因此改变。

电感原始测试不调用一次处理四路的 `Track_ReadAdc()`。ADC分压键不调用会初始化菜单、调参或持久化业务的整体入口。PC13只调用一个事件消费入口，不能再同时调用 `BSP_Key_StartPressed()`。

## 6. 板载屏数据布局

板载屏160×80，8×16字符，可用五行、每行20个字符。固定字段顺序写在操作说明中，屏上不放长标题。拟以100ms节流刷新，只改变显示频率，不改变中断采集周期。

### 6.1 灰度16路

前四行、每行四个四位整数，列起点为x=0/40/80/120，行起点y=0/16/32/48。

```text
0123 0456 0789 1023
1234 1567 1890 2123
2345 2678 2890 3123
3345 3678 3890 4095
```

顺序固定为ch0～3、ch4～7、ch8～11、ch12～15。第五行放本次采集状态、成功帧号及最近成功帧耗时（μs）。物理ch0最左/ch15最右仍需板测确认。

灰度失败保留上一完整帧，显示失败状态并改变数据颜色，避免旧帧冒充新帧；首帧成功前显示 `----`。直接读取BSP原始帧，不受当前32项黑白标定均为-1阻挡，也不填写虚假标定或绕过正常起跑门禁。

### 6.2 其他测试

| 测试 | 固定显示内容 |
|---|---|
| 单路电感、ADC分压按键 | 当前原始码、窗口最小值、最大值、峰峰值、读取次数 |
| 电池 | 原始ADC、滤波ADC、窗口最小值、最大值、更新次数 |
| 单轮编码器 | 最近1ms脉冲、累计脉冲、采集次数及可用的时序统计；累计来自每拍采集而非100ms显示快照求和 |
| DL1B | 本次距离、本次有效标志、最近有效距离、距最近有效值时间、无效次数 |
| PC13 | 最近事件码、短按累计次数、长按累计次数 |

窗口统计的具体大小及字段排布在实施规约中明确，不把此前前台采样方案的统计实现直接搬入中断。电池先显示ADC码，不在缺少核实分压比例时给出电池伏特值；编码器先显示脉冲，不在未确认脉冲数和轮径时给出RPM或mm/s。

前台只读取已发布快照，不再次采集。使用短临界区复制一致快照，绘图在临界区外执行；不得在整次LCD绘制期间关闭采集中断。显示允许覆盖旧的显示快照，不表示传感器可以跳过采集。

## 7. IMU至VOFA+的JustFloat上传

### 7.1 已确定的数据格式

- 测试串口：460800、8N1；仅在IMU测试模式采用该波特率。
- 陀螺、加速度为两个独立测试，各自上传三轴原始码转float。
- CH0=X，CH1=Y，CH2=Z；不消除零偏，不积分角度，不混入printf提示或其他业务数据。
- 每个TIM15采样生成一帧，按采集顺序完整上传，不采用抽样上传。
- 每帧：三个小端32位float，共12字节；随后四字节帧尾 `00 00 80 7F`，合计16字节。

官方格式依据：[VOFA+ JustFloat文档](https://www.vofa.plus/docs/learning/dataengines/justfloat/)。后续打包须核对float宽度、字节序与实际帧长，不靠未检查的结构体填充布局假定协议。

### 7.2 带宽与代码数据流

8N1每个字节占10个线路位：`16 × 1000 × 10 = 160000 bit/s`，约占460800的34.7%。理论带宽够用不代表实际持续发送已通过；USB转串口需支持该波特率并实测。

```text
TIM15每1ms
  → 读取当前测试的三轴原始值
  → 完整写入静态环形队列槽
  → 按单生产者规则发布写索引

前台
  → 按顺序复制待发样本到独立发送缓冲
  → 三轴原始值转换为float
  → 打包16字节JustFloat帧
  → 调用测试串口发送接口
  → 统计发送结果
```

队列必须使用静态存储；ISR为唯一生产者，前台为唯一消费者。索引发布顺序、内存屏障、槽释放时机及发送缓冲寿命需在规约中写清。不能在串口仍使用某个缓冲时让ISR覆盖它，也不能为等待串口腾位阻塞TIM15。

统计采集数、入队数、已确认完整发送数、队列溢出和发送异常。队列溢出不得静默标为“完整上传”；测试通过须有采集/发送计数和队列状态依据，不能仅凭VOFA+曲线连续。结束统计时要区分尚未发送的队列余量与真正丢样。

现有 `BSP_UART_Write()` 的失败返回语义存在已登记冲突，不能直接把其返回0当作严格成功证据。实现前须明确测试发送接口的成功/部分发送/失败语义；不在本报告中擅自改变正常UART公共接口。

队列容量、溢出后动作及发送异常处理尚未定稿，应先给出具体规约选项并确认，再实现。它们不改变已确定的目标：TIM15连续1kHz采集、每个样本完整上传。

### 7.3 连接与观察

根据现有工程，USART1为PA9/TX、PA10/RX；接线需核对实际板卡、电平与共地。VOFA+选择实际COM口、460800、8N1和JustFloat，按X/Y/Z顺序绑定三个通道。坐标轴时间尺度需按实际1kHz样本率核对，不能仅按界面重绘速度估计采样周期。

IMU测试期间不操作LCD，从而取消SPI4与屏幕交错访问。正常固件串口保持现有配置，USB转串口能力和实际链路稳定性均为待验。

## 8. 已知限制与未决实施细节

| 项目 | 当前处理与结论边界 |
|---|---|
| IMU读取错误发布 | 暂不修复；初始化失败不继续采样。初始化成功后的每次坏读数仍不能可靠判断，不设置虚假的“有效采样”通过结论 |
| IMU阻塞超时 | 驱动使用HAL阻塞调用，高优先级ISR中HAL时基能否推进需核对；1kHz为正常路径目标，不承诺故障连接下仍满足 |
| DL1B中断阻塞 | 保持TIM6测试上下文；其I2C阻塞及时基风险保留，不能把10ms超时参数解释成高优先级ISR中的严格退出上限 |
| 灰度标定 | 当前全部未填；本轮原始读取不宣告标定、归一化或质心功能通过 |
| 中断频率与执行间隔 | 定时器设定周期不等于已实测无抖动；必须核对IRQ计数、间隔、执行耗时和刷屏/上传影响 |
| 显示数据 | 100ms显示不保证看见每个1ms脉冲；累计、极值必须从采集端统计 |
| UART发送错误语义 | 测试接口方案待确认，不顺带重定义正常运行公共接口 |
| 队列与统计参数 | 容量、异常动作、窗口大小和时序验收容差须在实施规约中给出，不能把建议当成用户已确认值 |

本报告不引入休眠加速度积分、元素状态机或完整闭环控制，不把暂不修复解释为问题已获准永久保留。

## 9. 实施顺序与验收

1. 完成剩余具体设计：测试发送状态、队列容量/溢出动作、统计窗口、时序容差、精确文件/符号清单。存在影响行为的多种方案时，先由用户确认。
2. 在所属既有Phase与对应docs中记录需求、目标接口、错误路径、任务及验收；不自行新增Phase18。规约须先作不含实现代码的独立提交，本报告不能代替这一步。
3. 实现测试启动分支、最小初始化、唯一IRQ分派及LCD自身测试。
4. 实现电感、灰度、电池、ADC按键与PC13。
5. 实现左右编码器的按轮初始化和1ms采集。
6. 实现IMU原始采集、静态队列、460800/JustFloat上传。
7. 实现DL1B的TIM6独立轮询测试，并明确保留异常时序限制。
8. 对每个实际使用的测试宏分别构建、烧录并记录真实板测结果。

软件检查：格式/命名、中文Doxygen及注释内容、调用顺序、状态owner、错误路径、共享数据发布、IRQ周期/优先级与跨模块冲突；固件实现后按项目要求构建零错误零警告并维护R08。优先复用已有构建和检查工具，不例行新增宿主模拟脚手架。

板测检查：每次只施加一个外部变化；固定其他供电、安装高度、光照、姿态或接线条件。记录实际数值，缺少测量依据时不自行编造精度或噪声合格阈值。

记录模板：

| 字段 | 内容 |
|---|---|
| 测试身份 | 日期、固件完整提交号、测试宏、构建配置 |
| 硬件条件 | 板卡/模块、接线、供电、安装位置或姿态、辅助测量仪器 |
| 刺激 | 本次只改变的变量及具体操作 |
| 读数 | 屏幕字段或VOFA+三轴数据、极值/累计/错误统计 |
| 时序 | IRQ次数、实测周期/最长执行时间、显示或发送期间的变化 |
| 结论 | 已证实内容、失败现象、未验内容与证据位置 |

编译通过不替代接线、电气、测量精度、连续吞吐或真实周期验收。没有执行的板测保持待验，不改写历史结果。
