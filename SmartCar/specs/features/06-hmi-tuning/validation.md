## 自动化验证

```bash
cd SmartCar/MDK-GCC && bash build.sh
```

通过标准：编译链接完成，输出 `*** 完成：0 警告 0 错误，产物 MDK-GCC/SmartCar.hex ***`。
（本规约追认时点实测通过：text 59452 / data 236 / bss 10192，2026-10-02 基线。）

无单元测试框架（见 [techstack.md](../../techstack.md) 测试节）；菜单/串口协议无主机侧仿真，依赖人工上机。

## 人工上机步骤

1. **烧录**：`MDK-GCC/flash.sh`（OpenOCD + ST-Link），或 Keil 工程下载。
2. **上电自检**：串口 115200 可通信（时钟树正确）；板载屏显示仪表盘（默认配置）。
3. **按键核对**（V-4）：HOME 页逐键核对 K1/K2 显示值与需求表区间；若全部键无响应或两路数值对调，检查排线/接线是否接反（README 上机检查清单第 2 条）。
4. **导航与调参**（V-5 ~ V-7）：按页面表遍历全部页面与按键动作。
5. **串口调参**（V-11 ~ V-13）：串口助手发送协议帧，核对回显与生效。
6. **持久化**（V-8 ~ V-10）：调参 → 断电 → 重上电核对。⚠现状预期失败（Phase 08 修复后复测）。

## 回归检查

- 菜单/仪表盘代码不得影响控制拍：起跑后 TIM6(2ms)/TIM15(1ms)/TIM7(5ms) 时序不漂移
  （可通过 Phase 07 导出 CSV 的 tick 连续性旁证）。
- `LCD_TARGET_EXTERNAL` 两个配置分别编译均零警告。
- 按键扫描、串口解析全部发生在主循环停车态，不进入任何 ISR。
- 参数结构体 `param_store_t` 布局与 `PARAM_VERSION` 不被无意改动（改动即旧数据不兼容，须升 version）。
