- **FR-01 长期标准**：发布 `specs/code-style.md` CS-01～CS-15；协作入口在宪章/路线图后、
  功能规约前要求阅读，技术栈列为硬性约束，README 提供入口。以后每个实现提交都记录
  格式、命名、注释、例外和功能验证，不把现有混合风格当成继续沿用的依据。
- **FR-02 范围及例外**：精确文件白名单和 E-01～E-05 见符号表。67 个自维护 C/H 全量检查；
  21 个 Core C/H 仅限现有用户区，无内容的区域不修改。HAL/CMSIS、ST7735 厂商组件、字库、
  生成区、参考工程、汇编、链接和 `.ioc` 不在迁移范围。文件路径不变，不迁移模块职责。
- **FR-03 排版**：全部适用区域执行 CS-03～CS-05；展开多语句同排、单行函数和条件体，
  补齐大括号、统一空格和分段。保留 `for` 头分号及原有单条连锁赋值的执行顺序；不把早退
  改成其他控制结构，不缓存重复调用、不合并采样或条件判断，不改表达式与转换顺序。
- **FR-04 全量名称**：按符号表逐行迁移函数、类型、宏、枚举、全局/私有对象、不合规字段和
  局部量，已合规者保留。作用域、链接属性、存储限定符及初始化不变。公共名称同步头文件、
  手工 extern、所有仓库调用和测试夹具；不保留旧名兼容宏或转发接口。外部固定名称保持。
- **FR-05 注释**：全部自维护文件、公开接口、私有函数和状态字段按 CS-10～CS-13 补齐中文
  说明。公开契约写入参数单位/范围、指针条件、返回和失败行为、输出发布时机；涉及调度、
  阻塞、共享状态和 ISR 限制时写明真实约束。可核实的过时说明按当前代码纠正；不能从代码
  或既有决定确认的事实必须先问用户，不添加虚构物理单位、校准值或实测结论。
- **FR-06 龙邱采集驱动**：保持 `BSP/bsp_gray` 和 `bsp_adc` 的硬件职责，明确 0～15 选址、
  每通道五个新转换、丢三均二、完整帧后发布、失败保留输出、700 us 整帧预算与 DWT 回绕。
  保留 LQ_Track.c V2.0.0、作者/版权/许可、SHA256 和硬件适配差异。`App/gray_calibration.h`
  的 32 个 -1 不填写；App 标定、归一化、质心与有效性判定只改名/格式/注释，不下沉 BSP。

## 输入、输出及不变量

输入仍为既有 ADC/DMA、编码器、IMU、按键/串口、参数镜像和日志请求；输出仍为既有状态、
PWM、Flash 数据和通信文本。输入约束、错误码、失败时输出是否保持和共享状态写入均沿用
基线及 [Phase 14 契约](../14-dual-mode-tracking/requirements.md)，本阶段不新增运行时分支。

TIM15/TIM6/TIM7 保持 1/2/5 ms；TIM15 与 TIM6 优先级 0、互不抢占；灰度预算 336000 周期、
完整控制预算 432000 周期保持。D-Cache 关闭、DMA 目标 `0x30000000`、SPI45SEL 补丁、
硬件选择线、ADC rank 和工具链锁定保持。重命名不承诺重新完成实车时序验收。
