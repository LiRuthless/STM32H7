  C 标签按 brief/details/param/return/pre/note 排序，方向与实际形参逐项对应；void 等不适用
  标签省略。H 只有 brief/note 摘要。文件/阶段/字段/状态分别采用指定块，统一缩进、单空格、
  四空格续行、100 字符普通行宽及注释邻接；只保留明确登记的版权/来源和生成区例外。
- **FR-15 维护级完整性**：每函数解释职责、显式与共享输入输出、已确认单位/范围、状态写入、
  返回/失败语义及适用的前置/阻塞/ISR/持久化约束；复杂实现头部 details 与实际阶段说明都
  必须存在。纯 getter/转发/空壳省略 details 前须在 CF 中人工确认类别。不能把旧 H 文本机械
  搬到 C 后直接认定通过，不用“保持原逻辑”等过程描述代替解释。
- **FR-16 连续流程与事实**：按实际处理阶段组织解释，说明公式/符号、分支目的、操作顺序及
  失败保留状态，模块头解释职责/数据流/调用/状态归属/并发。对起跑检查、双传感器、归一化
  与质心、首次停车、日志发布/消费等建立连续阅读路径。数值依据无法确认时只陈述现有门限，
  不编造硬件或调参理由；Gray_Update 必须覆盖停车主循环、起跑门禁及 TIM6 三类实际调用。
- **FR-17 逐项清单**：comment-review 的每个 CF 登记当前缺项、类别、C 权威位置、H 摘要位置，
  分别关闭覆盖/格式/人工内容/token 保持；每个 CM 登记模块说明、字段/枚举、状态对象与来源
  区间。初筛类别不等于人工确认，已有块不等于合格；不适用项写对象级理由，不批量填同上。
- **FR-18 注释以外保持**：后续只调整注释，不改命名、C token、流程、类型/属性、数值、
  字符串、预处理结构、工程或测试。被注释算法仍不得激活；不重排非注释语句。检查器正确
  识别字符串/字符常量中的注释符号、转义及宏续行，比较每文件非注释 token 和预处理指令。
  文件/函数的注释位置变化不意味着可承诺调试行号或二进制字节完全相同。
- **FR-19 独立验收**：格式、覆盖、人工内容、token/预处理保持及既有功能回归分别记录。
