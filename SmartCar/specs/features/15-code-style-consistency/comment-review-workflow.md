# 每次提交的注释复核操作

2026-10-23。检查入口：`python SmartCar/tests/comment_review_check.py --base <完整基线提交>`。
默认记录：本目录 `comment-evidence.json`。从仓库根运行；Python 3.9+、Git 可用。

1. 本批开始记录基线（规约提交完成后的 HEAD），沿用规约先行流程。
2. 阅读变更模块的完整实现、头文件、调用方和配置；逐条检查职责、公式、单位、时序、状态、失败路径。
3. 只暂存本任务明确路径。根据实际暂存内容填写 JSON，而不是根据未暂存工作区填写。
4. 逐项写 items 的 object、fact、evidence；依据使用路径、确实存在的符号或表达式。
   登记所有跨文件事实依赖，特别是调用方、中断配置、硬件映射及算法输入来源。
5. 人工复核完成后，更新 sha256、dependencies、reviewed_base、reviewed_at 和四项 checks。
   内容无须修改时，在 content.reason 写为什么现说明仍正确。禁止只刷新摘要而不复核内容。
6. 暂存证据 JSON，运行检查入口；逐项消除失败后才能提交。检查器不生成 pass 或事实文本。
7. 若重新暂存了源码或证据依赖，重新检查并更新记录。部分暂存以索引内容为准。

记录结构见 [R08 契约](r08-review-contract.md)。摘要计算对象为 `git show :仓库相对路径`
输出的原始字节，不能用工作区文件摘要代替；Git 的换行转换可能使两者不同。
`reviewed_base` 可用 `git rev-parse <本批基线>` 得到完整提交 ID。
删除项保留记录，sha256 为 null，用 base_dependencies 和 revision=base 的依据追踪原定义；
新增、删除及改名须写 cleanup 说明调用/构建引用处理。Core 例外仍登记具体事实和证据，
检查器比较 USER CODE 标记与内容，拒绝用生成区例外隐藏用户区变化。

源文件或登记依赖发生变化，旧证据失效。清单不是全项目自动依赖图：人工仍须主动发现新依赖。
未登记的模块第一次变更时建立记录；不能因为十个文件通过就声称全部旧模块已复审。
更改检查器时执行 `python SmartCar/tests/test_comment_review_check.py`；测试仅在临时 Git 仓库写入。
本轮没有 Git hook，维护者需遵守提交前运行约定。

## R08 漏检原因与纠正

旧验收虽然分列内容检查，却没有把关键中文断言与当前源码及调用方建立可验证关联。
模板式调用顺序描述掩盖了模块职责、错误路径和运算顺序的差异；旧记录也不会随源码失效。
本次五模块由具体事实重新复核，逐函数证据同时覆盖对应 H 摘要；DL1B 寄存器封装和
Key_Init 属于单调用转发，getter 只直接读取缓存，其余计算/分支函数有明确阶段说明。
新增缺陷必须追查未登记依赖、审查遗漏或工具不足，并补充相应记录/测试，不能只改一句注释。
