# SmartCar C 代码写作标准

> 版本：1.0，2026-10-16 用户确认。本文是新增、修改和审查自维护固件 C/H 的强制标准。
> 存量全量迁移归 Phase 15，规约目录为 `features/15-code-style-consistency/`；
> 需求、实施计划、验证和命名映射将作为独立功能规约提交。
> 本文发布不代表存量代码已完成整改，也不授权开始代码实现。

## 1. 适用范围与执行

- **CS-01 适用范围**：`App/*.c/.h`、`BSP/bsp*.c/.h`、`BSP/lcd/lcd.c/.h`，以及
  `Core/` C/H 中已有 `USER CODE BEGIN/END` 标记之间的用户代码。
- `Drivers/`、`BSP/lcd/st7735.c/.h`、`BSP/lcd/st7735_reg.c/.h`、`BSP/lcd/font.h`、
  Core 生成区、启动汇编、链接文件、参考工程不作本标准的全量迁移。不得为排版扩大到生成区。
- 每次开工按 `AGENTS.md` 顺序阅读宪章、路线图、本文和功能规约。新增代码立即遵守；存量全量
  迁移按 Phase 15 执行。Phase 15 实现前，其他任务只在已获授权的修改范围应用标准，涉及旧符号
  改名仍先补充、提交对应规约，不能借风格检查扩大任务范围。
- **CS-02 持续验收**：每个实现提交前逐项检查 CS-03～CS-15，在所属功能验证文档记录适用项、
  例外和实际结果；无适用项写明原因。格式通过不能替代功能验证。本文不新增格式化器依赖，
  不以未安装工具为理由跳过检查；自动检查无法判断的命名和注释由人工审查。

## 2. 排版

- **CS-03 缩进与换行**：使用 4 个 ASCII 空格，不用 Tab；函数、条件、循环、结构体、枚举和
  多行初始化器的大括号独占一行；`else` 独占一行。`switch` 的 `case/default` 比 `switch`
  缩进一级，其语句再缩进一级。预处理指令的 `#` 位于行首，宏续行内容仍使用空格缩进。
- 每个 `if/else/for/while/do` 的语句体均使用大括号，包括提前 `return`、空循环和单条调用。
  空函数或空分支也展开大括号；在块内说明必须保持为空的原因。不得为排版改动条件、增加分支
  或把原有顺序分支合并为 `else if`。
- 一行一条可执行语句；一条声明只声明一个对象或字段。`for` 头内两个分号不属于违规；单行
  数组允许逗号分隔标量，前提是满足行宽且无逐元素说明。连锁赋值作为原有单条语句可以保留，
  不得为样式更改易变对象的写入顺序。
- **CS-04 空格**：写作 `if (condition)`、`for (...)`、`switch (...)`；函数调用写作
  `Function(argument)`。二元及赋值运算符两侧各一空格；逗号后留一空格、前面不留；一元
  `!/~/*/&/++/--` 与操作数相邻；`.`、`->` 和下标内部不插空格。
  指针声明写作 `const type_t *name`；类型转换写作 `(int16_t)value`；`sizeof` 统一带括号。
- **CS-05 行宽与分段**：代码行最多 100 个字符，Tab 不计为替代空格。先在参数逗号、逻辑
  运算符或算术运算符处换行，续行比该语句首行多缩进一级，运算符留在续行开头；不重排表达式。
  完整串口/CSV/格式字符串、不可分割的来源 URL/校验值/版权原文可超过 100，必须能从其内容
  直接识别为这些例外；不据此允许普通注释或函数声明超长。
- 函数定义之间空一行；同一函数内按处理步骤空一行，不连续堆叠空行。删除行尾空白，文件末尾
  保留一个换行。新增 C/H 使用 UTF-8 无 BOM；修改文件保持原有换行符，不作全文件换行转换。

## 3. 命名与文件组织

- **CS-06 函数**：自维护函数统一 `Module_ActionObject`，动作部分为 UpperCamelCase；
  公共和 `static` 函数采用同一规则，保留各自链接属性。例：`Track_ReadAdc`、
  `Motor_UpdateControl`、`PID_UpdateSpeedLeft`。BSP 使用 `BSP_Module_ActionObject`，
  如 `BSP_Gray_ReadFrame`、`BSP_ADC_Read`。模块前缀以 Phase 15 映射表为准。
- 既有模块前缀 `App/Control/Tracking/Dashboard/Datalog/ElectromagneticFSM/Element/Filter/Gray/
  IMU/Menu/Motor/OpticalFSM/Param/PID/Roundabout/Track/Wireless` 保留此拼写。
  BSP 模块为 `ADC/DL1B/Encoder/Flash/Gray/IMU660RB/Key/LCD/LCDIO/PWM/Sampler/Time/UART/
  W25Q64/WDT`，斜线表示分别接在 `BSP_` 后。动作中的普通缩写写作 `Adc/Crc/Io`，已有合规
  接口里的硬件缩写 `ISR/Mm/1ms/64K` 保持原拼写，不为大小写迁移制造第二轮改名。
- **CS-07 类型与对象**：自有类型用模块小写前缀、下划线和 `_t`，例如 `filter_lowpass_t`、
  `pid_speed_pi_state_t`。成员、参数和自动局部变量用 `lower_snake_case`；允许已有通用
  短名 `i/j/x/y/z/ch/id/n/p`，含义须由局部上下文或参数注释明确。
- 外部链接对象统一 `g_<module>_<name>`，包括仅在本文件使用但仍具有外部链接的对象；
  静态存储对象统一 `s_<name>`，包括静态局部变量和静态常量数组。自动局部变量不加 `g_/s_`。
  不以命名整改为由改变 `static/extern/volatile/const`、作用域、初始化位置或存储分配。
- **CS-08 宏、枚举与保护宏**：自有宏、枚举项使用模块前缀和 `UPPER_SNAKE_CASE`。
  枚举底层数值、位位置和数组下标不变。头文件保护宏统一
  `SMARTCAR_<目录>_<文件主名>_H`，例如 `SMARTCAR_APP_TRACK_SENSOR_H`、
  `SMARTCAR_BSP_LCD_LCD_H`；不使用双下划线或下划线加大写字母等实现保留标识符。
- **CS-09 文件组织**：模块文件名使用小写下划线，已有文件路径保持。顺序为文件说明、
  包含、私有宏/类型、对象、私有函数声明、函数实现。头文件按依赖、公开类型/常量、公开接口
  分组。本轮存量整理不调整包含顺序或声明初始化的执行顺序，避免宏、属性和副作用变化。
  App 仍经 `bsp.h` 接触硬件；本标准不批准新增 HAL 依赖或迁移现有职责。

## 4. 注释

- **CS-10 文件说明**：每个自维护 C/H 使用 `/** ... */`，包含 `@file`、中文 `@brief`，
  说明模块职责、层次及相关调度入口。移植文件另注明源文件、平台、版本、作者、许可证和
  对应规约；原版权/许可声明保留原文，不能替换为“本项目原创”。
- **CS-11 函数契约**：公开函数的权威说明放在头文件声明前；私有函数放在定义前。
  每个函数至少有中文 `@brief`。每个参数用 `@param[in/out/in,out]` 写含义、单位及合法范围，
  指针写明空指针前置条件和输出写入时机；非 `void` 返回用 `@return/@retval` 写真实取值和
  失败语义。`void` 不堆叠空的返回说明。需要初始化、限于停车调用、允许/禁止 ISR 调用、
  会阻塞或改变共享状态的函数用 `@pre/@note` 明确说明。
- C 定义前不重复整段公开契约；解释算法或执行限制即可。仅有 C 定义而无公开声明的现有
  外部函数，在定义前写契约，不为补注释新增导出接口。
- **CS-12 字段和关键逻辑**：结构体每个自有字段有中文含义说明；存在物理/计数单位、有效
  范围、无效哨兵或并发归属的字段同时写明这些事实。全局/静态运行状态注明用途与读写上下文。
  使用 `/**< ... */` 写字段说明，使用 `/* ... */` 写块内说明。
- 注释解释选择原因、错误路径、状态/时序约束，而非逐句翻译赋值。起跑门禁顺序、停车首次原因
  与累计保护位、DMA 新样本判定、完整帧发布、DWT 回绕、日志发布次序、整数截断及配置表部分
  覆写必须有对应说明；公共契约和源码保持一致，不写尚未完成的功能或“已实测”承诺。
- **CS-13 休眠代码与未知事实**：休眠函数、保留入口及被注释算法注明当前不接入和出处，
  维持现有调用关系。被注释代码中的本地旧符号同步映射以免以后误用，但来源文件名、历史证据、
  协议字符串不作替换。无法从代码和规约确认的含义先询问用户，不能以猜测注释掩盖未决项。

以下片段只演示公开声明的说明格式，不是新实现：

```c
/**
 * @brief 读取一帧 16 路原始灰度。
 * @param[out] out 输出帧；成功后才整体写入，失败时保持原内容。
 * @retval BSP_GRAY_OK 成功，帧序号增加一次。
 * @retval BSP_GRAY_ARG out 为空。
 * @retval BSP_GRAY_TIMEOUT 整帧达到 700 us 预算。
 * @retval BSP_GRAY_DMA_ERROR DMA 不可用或出现错误。
 * @pre 已完成 ADC DMA 和灰度模块初始化。
 * @note 停车主循环或 TIM6 调用；有界阻塞，不输出半帧。
 */
bsp_gray_status_t BSP_Gray_ReadFrame(bsp_gray_frame_t *out);
```

## 5. 固定名称与行为边界

- **CS-14 固定名称**：HAL 的强符号回调、向量表中断入口、`main`、CubeMX 的 `MX_*`、
  `SystemClock_Config/Error_Handler`、运行库 `fputc`、厂商类型/字段/对象及寄存器名称保持。
  函数指针注册的自有回调不因“回调”二字自动豁免，须按模块规则命名。
- Core 生成区的 HAL 句柄、引脚宏和配置字段保留 CubeMX 拼写，用户区引用不改写这些名称。
  链接段名、编译器属性、内联汇编、CRC 覆盖范围、Flash/CSV/串口内容不属于可改名的 C 符号。
  Phase 15 的固定名称与排除清单为本次完整清单；后续新增例外必须在规约说明外部约束证据。
- **CS-15 行为保持**：排版、注释和改名不改变类型宽度、布局、数值、计算和转换顺序、短路
  求值、对象写入顺序、初始化时机、状态转移、临界区边界和中断优先级。不得附带抽取流程、
  修复已有行为、激活/删除休眠入口、重构宏、修改串口文本或重新标定参数。
- 公共 C 名称迁移必须同步全部仓库内调用方、测试夹具和现行规约引用；不能靠旧名兼容宏掩盖
  未迁移调用。历史验证记录和源工程名称保留，追加映射指引以保持追溯。

## 6. 每次变更检查表

1. 核对文件在 CS-01 范围内，规约已先行提交，本次符号变更已列出。
2. 按 CS-03～CS-09 核对格式、命名、声明与固定名称；超长例外逐条确认类别。
3. 按 CS-10～CS-13 核对说明和真实代码一致，公共接口、私有函数及状态字段无遗漏。
4. 按 CS-14/15 核对第三方/生成代码边界和行为不变量，检查相关调用方及测试引用。
5. 执行功能规约要求的构建/测试，记录实际结果；检查差异范围后仅暂存本任务明确路径。
