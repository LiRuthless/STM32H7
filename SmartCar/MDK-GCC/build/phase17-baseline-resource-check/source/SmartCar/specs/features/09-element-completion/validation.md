## 自动化验证

- `MDK-GCC/build.sh` 构建通过、**零警告**（每个 Group 提交前必跑）。
- 代码审查确认：`element_judge` 等休眠壳的调用关系与 plan 描述一致（接入或显式保留，无新增死代码）。

## 人工验证步骤

1. 每接入一个元素前，先在无该元素的赛道上跑一圈作基线（记录直道/十字/右环岛行为）。
2. 接入后跑含目标元素的赛道：观察实车行为，停车导出 CSV，按 `kernel_state` 列核对状态转移序列与预期一致。
3. 阈值标定：误触发则收紧门限，漏检则放宽；每次改动记录数值与理由，标定结论回填 [plan](plan.md) 对应 Group。
4. 全部元素接入后做一次全流程回归（下节）。

## 回归检查

- 无元素直道：不偏航、不误入任何元素状态。
- 十字路口：直线通过，行为与整改前一致（基准见 [Phase 04](../04-element-fsm/validation.md)）。
- 右环岛：进入/环内/出环行为与整改前一致；左环接入不得改变右环路径。
- 停车与保护：出赛道停车、低压停车、看门狗行为不变。
- 串口调参与菜单显示（含状态监视）不出现乱码/异常值。
