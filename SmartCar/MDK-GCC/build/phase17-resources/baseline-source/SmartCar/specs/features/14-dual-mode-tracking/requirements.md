## 功能需求

### 灰度采集与偏差

- **FR-01 来源可追溯**：按上述源文件、校验值和下表记录函数映射。移植前校验附件；文件缺失或校验不符时先核对版本，不替换为网络上的同名库。
- **FR-02 引脚与选择顺序**：S0=PE4、S1=PE6、S2=PE0、S3=PE1，PC4=`BSP_ADC_GRAY`。四线推挽输出、无上下拉、初始化为 0000；通道 `ch=0..15` 的 S3:S0 为 ch 的二进制。`.ioc`、`gpio.c` 和 BSP 同步，ADC 十个 rank、采样时间及其他引脚不变。
- **FR-03 真实新采样**：每通道只设置一次选择线，随后等待五个不同的 PC4 DMA 更新，丢弃第 1～3 个，将第 4、5 个 12bit 值用 `uint32_t` 相加再整除 2。ADC1 持续扫描，其他通道继续采集。通过 DMA 硬件计数推进识别新转换，不等待优先级 2 DMA 回调在优先级 0 内执行；禁止五次紧密读取同一 DMA 单元。
- **FR-04 帧发布和时限**：整帧 16 路写入临时缓冲，仅成功后整体发布并增加 `uint32_t sequence`；失败保留上一完整帧和序号，同时设置失败状态。原始值 0～4095、显示百分比 `raw*100/4095`。从第一条选择线写入至最后一次有效采样的预算为 700μs，耗时达到预算仍未完成即超时；不能发布部分新、部分旧的数组。
- **FR-05 手工标定配置**：新增 `App/gray_calibration.h`，集中列出 16 路 `int16_t` 黑底值和白线值，未填写哨兵为 -1；各项只有落入 0～4095 且 `abs(white-black)>=200` 才有效。0 是合法实测值，不能作为未填写哨兵。上电和起跑前校验全部通道，串口报告全部不合格通道；任一不合格均阻止两种模式启动。填写值和物理左右方向由用户实测，文档不提供伪造的示例标定。
- **FR-06 灰度强度和权重**：中间计算至少 `int32_t`，`q_i=clamp(1000*(raw_i-black_i)/(white_i-black_i),0,1000)`；除法遵守 C99 向零截断。`q_i<50` 置零，等于 50 保留。`max(q_i)<200` 失线，等于 200 有线。通道 0 在左、15 在右，权重 `w_i=15-2*i`；`error=100*sum(w_i*q_i)/(15*sum(q_i))`，向零截断，结果 ±100。分母零返回 error=0 且 `line_valid=0`，不能把 0 偏差当作有线。
- **FR-07 双采集调度**：停车主循环刷新两套读数供标定/观察；运行后从第一个 TIM6 控制拍起每 2ms 更新电感和完整灰度帧，包括起跑等待期。电感保留现有八读、去极值、六读平均语义，不声称这八读来自不同转换。TIM15 每 1ms 取最近完整控制快照，允许相邻记录的传感器序号相同；同一逻辑快照不等于四路电感及16路灰度在同一瞬间采样。原来 2 秒内电感不刷新的路径不得保留。
- **FR-08 分层接口与时基**：App 不直写 GPIO、ADC、DMA 或 DWT。新增接口按后文定义，返回只读模块状态。DWT 在 BSP 初始化为自由运行 32bit 周期计数，以无符号差值处理回绕；每次测量不得清零计数器，不依赖 SysTick 在高优先级 ISR 内推进。700μs 对应 336000 个 480MHz 周期；900μs 对应 432000 周期。

### 状态机与输出隔离

- **FR-09 光电状态机**：枚举值固定为 `OPTICAL_WAIT=0`、`OPTICAL_TRACKING=1`、`OPTICAL_LOST=2`、`OPTICAL_STOPPED=3`。上电/模式切换/新一轮起跑复位为 WAIT；有效起跑后 `g_app_control_ticks>APP_RUN_DELAY_COUNT(1000)` 且双传感器有效时进入 TRACKING；任何运行拍灰度失线进入 LOST 并请求停车；其他停车原因进入 STOPPED。LOST 保持到下一次显式复位。即使选中电磁，光电观察状态仍按相同采样、延时和停车输入推进。首版不添加灰度十字、环岛或自动寻线动作。
- **FR-10 电磁独立状态**：保留现有 TRACKING/CROSSROADS/REISLAND/ISLAND_R 的主状态及右环岛子状态转移和所有严格/非严格不等式，见下表。电磁状态每个实际控制拍推进，光电模式下也记录所到状态；等待起跑期间保持初始状态。上下文独占权重、配置历史、环岛标志、路障抑制、左右相对里程、角度参考点及子状态。未选中时不得写实际 PID 增益、基础/目标速度、PWM、共享里程或 IMU 角度，不得调用含这些副作用的旧 judge 函数来冒充观察器。
- **FR-11 唯一执行者**：控制协调器先取得完整传感器快照并判断保护，再推进两套状态，最后只执行选中模式的控制意图。光电使用其归一化误差、参数 bank 和独立方向历史，电磁使用其原公式、状态配置及独立方向历史；不得用光电误差覆盖 `Track_GetState()->error`。两模式共用现有差速、速度 PI、编码器滤波、方向极性和 PWM 标度。光电不得调用电磁状态配置来设定实际方向参数。

| 电磁条件/顺序 | 状态变化与上下文动作（选中电磁时保持原动作顺序） |
|---|---|
| TRACKING：竖和>2800 且 symmetry_y<25 | CROSSROADS；随后仍执行同一旧分支内的预环岛判断，不增加互斥 return。 |
| TRACKING：横和>2800 | 横左>横右置左标志，否则置右标志；清自身路障标志、角度参考、左右相对里程，进入 REISLAND。同拍十字和预环岛同时成立时，预环岛按原调用顺序覆盖十字。 |
| 预环岛判断尾部 DL1B<100mm | 置自身 cask 标志；只沿用既有环岛抑制用途，不启用路障入态。 |
| CROSSROADS：竖和<2800 | 返回 TRACKING；该态实际方向输出限幅 ±10；影子态只记录状态，不限幅光电输出。 |
| REISLAND：竖和<300、右标志真、cask 假 | 进入 ISLAND_R/ISLAND_LPREENTER，清自身方向历史相关输出、角度参考、相对里程；随后执行原超时判断，使用清零后的本上下文里程。 |
| REISLAND：自身均值里程>5000 | 返回 TRACKING、清左右标志及自身输出/角度参考。 |
| 右环岛相对里程依次 ≥8000、>13000、>32000、>10000 | 预入环直行→固定打角→环内循迹→出环直行→TRACKING；各原清零点只清本上下文里程。实际电磁打角保持 `Motor_DistributeSpeed(-30)`；影子不执行。 |

电磁相对左右里程分别累计与原 `Motor_ReadEncoder` 一致的左右滤波增量，均值仍为 `(left+right)/2`，禁止每拍先取均值再累计造成截断差异。累计顺序保留“本拍状态判断使用上拍已更新里程，随后编码器读取”的既有契约。角度以 IMU 本拍积分增量累计到独立参考，虚拟清零不调用 `IMU_ZeroAngleX()`。影子状态表示实际光电行驶轨迹上的电磁判断，不是对假想电磁行驶轨迹的预测。

### 参数、按键与持久化

- **FR-12 并列参数**：共用当前档位 `LOW=0/HIGH=1`，每档各有电磁和光电 `KP/K2P/KD/base_speed`。光电两档初值均 `{2.0f,0.008f,15.0f,100}`，K2D 固定 1；速度 PI 20/0.75 和原两档运行/空闲风扇参数仍共用。光电 TRACKING 每拍读取本模式、本档参数；电磁保留当前状态表的每拍覆写数值、字段存在标志及顺序。电磁运行期调参被状态表覆盖这一既有 Phase 10 问题仍保留，不得声称本阶段已修复。运行配置及影子配置不得回写另一模式的持久化 bank。
- **FR-13 模式与 PC13**：每次上电设置 `TRACKING_MODE_OPTICAL=1`、LOW，不保存模式；电磁为 `TRACKING_MODE_EM=0`。稳定按下/释放均 30ms 消抖，按下不足 1000ms 的有效短按在稳定释放后生成一次 START；达到 1000ms 的长按立即生成一次 TOGGLE，持续按住不重复，释放不生成 START。运行中两个事件均忽略，停车后必须见到稳定释放才重新接受按下，上电按住也须先释放。切换只在停车、收尾完成后执行；先把待保存修改按旧模式旧档保存，失败保留模式并回显失败；成功后切换、清两套运行历史、加载新模式当前档方向参数。切换不改变档位，不起动定时器，不更新 Flash 中的模式字段。
- **FR-14 HMI 与串口路由**：菜单原 11/12 调参页及原步进不变，方向三项和基础速度访问当前模式，风扇访问共用档位。第一页标签使用 `O1 KP/O2 KP/E1 KP/E2 KP` 标出模式和档。板载仪表盘原 K 区域显示四字符 `O1K0` 等：模式、档位、K、当前电磁主状态；其他原监视数据保留，光电状态和电磁子状态完整进入日志。停车串口 `xp/xd` 编辑当前模式的 KP/KD，`vp/vi` 仍共享，帧长、数字规则、回显及三秒静默保存不变；不增加光电专用命令字、不扩展 K2P/base/档位的串口设置。模式切换输出 `track mode: optical\r\n` 或 `track mode: em\r\n`，启动拒绝原因另行回显。
- **FR-15 参数 v3**：固定采用后文 88B 布局、原 magic 和 CRC16-CCITT。有效 v2 的原 56B 字段值保留，追加两档光电初值；有效 v1 先按 Phase 08 规则补空闲风扇 1100，再追加光电初值。仅改变 version 和 CRC 所需值，不以新默认覆盖用户旧方向/速度/风扇参数。未知版本/CRC 错误沿用默认值并报告的路径；读写失败视为存储不可用并禁止起跑。保存从显式的模式/档参数 bank 取值，不从另一模式或影子状态实际寄存的 PID 值倒推。灰度标定、模式及运行状态均不落入此镜像。

### 统一保护、日志及兼容性

- **FR-16 停车与起跑门禁**：新鲜灰度帧失线、电感四路和≤300、灰度采集失败、TIM6 总耗时达到 900μs、低压或任一日志故障均进入 `App_RequestStop`；当拍切断两路 PWM、清目标/速度 PI、风扇回当前档空闲值，停止 TIM15/TIM6/TIM7，主循环收尾。保留首次停车原因，另记录全部已观察到的保护位；保护先于控制输出，发出请求后不得再执行编码器/电机控制。启动前必须完成全部手工标定校验、一次成功的双传感器读取及有效性检查、待保存参数刷新、可用日志会话头写入，任一失败均不置启动标志、不启动定时器。起跑等待期持续检查双保护，驱动输出仍保持零，保持原 `g_app_control_ticks>1000` 的驱动启用边界。再次起跑清两套状态/历史与采样序号，保留标定和用户参数，不重新执行 IMU 上电零偏校准。主循环进入停车采样/LCD/调参分支后，必须再次检查并完成待处理收尾；即使停车中断发生在循环顶部收尾检查之后、运行/停车分支读取之前，也不得先刷新界面或解析命令。
- **FR-17 日志固定格式**：按后文 little-endian 布局写 256B 会话头和 96B 记录，保留参数区 `0x7FF000..0x7FFFFF`，日志区仍为 `0..0x7FEFFF`。前 256B 专供会话头；记录容量 `floor((8384512-256)/96)=87336`，1kHz 时 87.336s。两种模式都记录四路电感、16 路灰度原始值、两套误差/状态、活动模式和保护标志。归一化灰度可由本次会话固定标定和原始值确定，CSV 必须输出两者。
- **FR-18 生产者与一致性**：TIM15 仅做有界快照和入队；使用 1024 槽、保留一个空槽区分满/空，实际待写容量 1023 条、分配 98304B，head/tail 至少 `uint16_t`。TIM6 与 TIM15 同优先级，控制快照在本拍数据、状态、活动输出全部完成后发布；TIM15 只能读完整快照。每 1ms 一条，量测帧每 2ms 更新，通过控制序号和灰度序号区分重复；禁止 Flash、UART、LCD、动态分配、等待 DMA 或标定计算进入生产者。
- **FR-19 主循环写入**：从 TIM7 移除 `Datalog_Flush`，运行态 `App_Loop` 每次最多刷八条=768B=三个 Flash 页，不在一次调用内无限追赶；少于八条时运行态不刷，停车健康收尾刷余量。首条数据偏移 256，八条批次保持页对齐；96B 不整除 256B，不能继续使用“每条记录一页内独立”的假设。BSP 继续按页拆写、按需跨扇区擦除；前台消费者只在成功后发布 tail，不提前复用 Flash 仍在读取的批次。TIM7 只负责既有电池保护、看门狗和状态灯。运行态主循环不刷新 LCD、不解析调参，SPI1 日志允许被 TIM6/TIM15 的 SPI4 任务抢占。
- **FR-20 日志故障**：`DATALOG_ENABLE=0` 或分频非 1 时报告配置不满足本阶段并禁止起跑；Flash不可用/会话头写失败禁止起跑。运行中缓冲满、写错、容量耗尽分别锁定故障并请求停车，不允许静默丢记录继续行驶。容量按“已写+待写”检查，以生产者独占的accepted累计计数作权威总数，避免并发读written/tail产生重复统计；最后一个合法槽可入队，随后请求容量停车，不产生越界记录。缓冲满时本条未接受快照计入 rejected 计数；故障后停止新增记录，写错后禁止重试同一失败写入，健康日志仍能刷出已经接受的余量。若存储已故障，停止原因和计数至少保留在 RAM 并于主循环串口报告，不能承诺故障记录一定写入 Flash。停止/导出不会清除故障锁存，只有新会话初始化清除；一次故障不产生重复停车报告。
- **FR-21 导出与旧数据**：串口 d/c 仍仅停车处理；d 输出版本元信息、固定 CSV 表头、全部成功落盘记录和状态尾行，最后仍为 EOF。c 只复位日志，不启动记录，也不能伪造缺失标定。固件升级前必须导出旧日志，新固件不解释无 v2 会话头的旧 32B 内容；不新增断电续录、自动恢复条数或多会话功能。新一轮起跑仍覆盖上次会话。无有效会话时报告原因并输出 EOF，不生成假数据行。
- **FR-22 实施边界与追溯**：只移植灰度与集成本阶段所需接口，不升级工具链/HAL，不改三线周期/优先级、D-Cache、SPI45SEL 补丁、速度 PI、占空比/编码器方向。新增 GCC 文件由现有通配构建收集；Keil 工程显式登记新源文件，ADC/GPIO 配置以 `.ioc` 为源。不得接入任何休眠元素、增量式 PID 或 IMU 速度积分。每条 FR 必须在计划与验证表有映射；上一轮仅验证文档；2026-10-16已完成实现与宿主功能验证，实车保持待上机，证据见validation.md。

## 接口与格式契约

以下固定接口已按规约实现；指针参数前置条件为非空，未知 mode/gear 拒绝且不改变状态。getter 返回静态模块对象的 `const` 指针，不暴露可写上下文。

| 接口/类型 | 输入、输出及失败 |
|---|---|
| `BSP_Time_Init()` / `BSP_Time_GetCycles()` | 初始化并读取自由运行 DWT；计数单位为一个 CPU 周期，回绕采用无符号差值。 |
| `BSP_ADC_ReadGrayFresh(uint16_t *value, uint32_t deadline_start)` | BSP 私有于灰度链使用；原始 DMA 值>>4。先观察 NDTR 在 rank5 之前，再观察 rank5 DMA 已写入，确认新转换；deadline_start 为本次整帧开始周期，超过 336000 周期返回超时。返回 OK/ARG/TIMEOUT/DMA_ERROR，失败不改 *value。DMA 缓冲按易变硬件数据读取，不能缓存 NDTR 或样本。 |
| `bsp_gray_frame_t` / `BSP_Gray_Init()` / `BSP_Gray_ReadFrame(bsp_gray_frame_t *out)` | 帧含 `uint16_t raw[16]`、`uint32_t sequence/scan_cycles`；ReadFrame 返回上述状态，失败不改 out，成功才增加序号。 |
| `gray_state_t` / `Gray_Update()` / `Gray_GetState()` | raw[16]、percent[16]、strength[16]、int16 error、sequence、scan_cycles、calibration_valid、line_valid、acquisition_status；Update 执行采样/校验/计算，错误状态独立于上一完整帧保存。 |
| `tracking_state_t` / `Tracking_GetState()` / `Tracking_TrySetMode(mode)` | 状态含 mode、gear、active_error、track_out、control_sequence、protection_flags；TrySetMode 仅停车可用，返回 OK/BUSY/SAVE_FAILED/ARG，失败保留模式、参数和历史。 |
| `OpticalFSM_Update(inputs)` / `OpticalFSM_GetState()` | 更新上述四态及光电控制意图；getter 不返回可写 PID 历史。 |
| `ElectromagneticFSM_Update(inputs)` / `ElectromagneticFSM_GetState()` | 输入是只读传感器及运动增量，输出上下文主/子状态及控制意图；无硬件和共享状态写入。`control.c` 仅在选中电磁时提交意图。 |
| `Param_GetDirection(mode,gear)` / `Param_SetDirection(mode,gear,profile)` | profile 含 float kp/k2p/kd、int16 base_speed；合法索引的 getter 固定非空。setter 不跨 bank，保持原菜单/串口允许的数值语义，保留 int16 速度和 float32 增益类型。 |
| `Param_TryFlushPending()` | 返回 1=无待保存或全部保存成功，0=写入失败；保留既有 void 保存入口供兼容，由新入口把失败传至切换和启动门禁。 |
| `BSP_Key_PollEvent()` / `BSP_Key_RequireRelease()` | 返回 NONE/START/TOGGLE；RequireRelease 在上电、停车和起跑后抑制残留按住。原 StartPressed 不再承担模式选择，应移除其应用调用。 |
| `Datalog_GetStatus()` / `Datalog_Service()` | 返回只读 active/fault/accepted/written/rejected/pending；Service 每次最多八条。`Datalog_Flush` 为兼容入口转调 Service；完整停车排空在主循环显式有限循环执行。 |
| `Datalog_SetStopSummary(reason, flags)` | 只锁存本会话首次停车原因并累计保护位，不做IO；模式切换不清除此会话摘要。主循环停车报告和CSV尾行读取该摘要，即使停止后没有新的TIM15记录也能复盘触发原因。 |
| `app_stop_reason_t` | 保留 NONE=0/OFF_TRACK=1/LOW_BATTERY=2，追加 GRAY_LOST=3、GRAY_ACQUIRE=4、CONTROL_OVERRUN=5、LOG_OVERFLOW=6、LOG_WRITE=7、LOG_FULL=8。电感失线沿用 OFF_TRACK；起跑拒绝不伪造运行停车事件。 |

同拍保护位固定为 bit0电感失线、bit1灰度失线、bit2标定不合格、bit3采集失败、bit4控制超时、bit5日志溢出、bit6日志写错、bit7日志满、bit8低压；其余为0。第一次停车原因按实际首先调用锁定；同一 TIM6 拍同时发现时按采集失败→灰度失线→电感失线顺序请求，保护位仍记录全部条件。900μs 检查在 ISR 退出前覆盖全部控制工作，一旦达到则立即补发停车请求；不得通过忽略失败路径耗时满足验收。

日志fault编号固定为 NONE=0、CONFIG=1（关闭/分频错误）、UNAVAILABLE=2、HEADER=3、OVERFLOW=4、WRITE=5、FULL=6、READ=7；首次故障锁存，导出读错不覆盖先前故障。READ仅结束停车导出，不伪造运行期停车事件。`Datalog_Start`继续以0为成功、非0为失败，具体原因从状态接口读取。

### CSV v2

保留外层 `dump start\r\n` 和末尾 `EOF\r\n`。先输出 `#log_version=2,record_size=96,mode=<0|1>,gear=<0|1>`；其后两行 `#black,<16项>`、`#white,<16项>`；再输出以下列序：

`tick,adc0,adc1,adc2,adc3,spdL,spdR,err,tout,gx,gy,gz,dl1b,bat,kstate,rstate,gray0..gray15,q0..q15,em_err,opt_err,mode,opt_state,gray_valid,protect,reason,gray_seq,control_seq`

其中 `gray0..gray15` 和 `q0..q15` 均展开为16个独立列，表头共57列；q 按本会话标定及 FR-06 重算，标定不合法的会话拒绝导出数据。整数十进制，err 是实际选中模式偏差，kstate/rstate 是电磁观察状态。尾行 `#status,fault=<编号>,accepted=<数>,written=<数>,rejected=<数>,pending=<数>,reason=<首次原因>,protect=<累计保护位>` 是 RAM 会话状态，不宣称它在掉电后恢复；该摘要在模式切换后仍保留至下一次会话初始化。CSV 行缓冲至少512B，发送长度不得超过实际缓冲内容；读出失败报告 `#dump_error=read` 后结束，不把 EOF 当作全量读取成功的证明。
