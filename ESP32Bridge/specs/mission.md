# 使命

## 愿景与受众

将ESP32-S3-DevKitM-1作为STM32智能车与电脑之间可验证的SPI/Wi-Fi桥接器，服务开发者、联调人员及维护者。阶段状态统一见[roadmap](roadmap.md)，现行功能见[Docs](../Docs/index.md)。

## 范围

范围内：SCB帧与可靠会话、SPI从机、WPA2 SoftAP、单控制TCP/订阅UDP、有界转发与背压、事件/导出生命周期、诊断及构建验证工具。
范围外：车辆参数语义、应用拍和持久化结果、元素/停车策略、STM32/电脑产品及硬件的实现维护；不依赖PSRAM，不缓存整份日志，不自动重放设置或复位设备。
本治理只约束ESP32Bridge，不扩大至SmartCar、Tools、Hardware或Material。

## 成功标准

1. 有效需求经稳定功能条目定位真实代码/状态owner和可判定验证。
2. SPI推进不等待网络；可靠接管前预留，拥堵/断线损失可归因，不伪造业务生效或保存。
3. 构建与资源证据真实，主机/目标/实机和历史状态分开；整机桥接不能由局部服务存在推定。
4. 未决行为由用户决定，契约独立提交先于实现，功能文档跨阶段持续维护。

## 治理原则与语言

Phase保存完整阶段设计、决定、任务、映射与验收；Docs维护当前功能说明，目标保存在Phase；源码是实现事实。冲突登记，不默认以代码批准设计。采用可判定中文与真实API/单位，不用“正常”等空泛结论。
执行步骤见[AGENTS](../AGENTS.md)，历史授权和原进度不在使命重复，见[治理历史](research/2026-11-05-governance-history.md)。

## 2026-11-07 现行文档体系

mission、techstack、roadmap、code-style及AGENTS共同约束需求、设计、实施与验收。体系为前层治理文档 → Phase → Docs ⇄ 代码。Phase完整保存背景、需求、详细设计、用户决定、计划、文件与符号映射、验证标准和实际结果，按阶段基线解释，不缩减为摘要跳转。Docs说明当前功能、算法、状态、时序、参数、错误和限制，与代码语义对应。目标草案和未开工组设计保存在Phase。

后续变更：Phase确认并独立提交 → 先更新本组Docs → 紧接实现 → 双向核对 → 匹配Docs与代码同批交付。短暂领先标明“本组实现同步中”、所属Phase/任务组及更新前代码基线，完成前取消。显式关闭阶段后的独立修改新增Phase；进行中的阶段可以补组与回填，不能覆盖历史决定及结果；软件完成但硬件待验不自动关闭。
