# G-02：SPI 会话变化的电脑通知

2026-10-18 用户明确确认：**关闭 TCP，重连后用 HELLO/HELLO_ACK 获取状态**。

## 事实与选择

[SCB/1](../../protocol/scb-v1.md) 已规定换会话清除传输缓存、未应用请求和订阅，旧会话不得继续执行或导出，但未规定电脑通知消息。用户选择关闭连接的方案；不增加 EVENT 类型或其他线格式。保持 TCP 并新增通知的候选方案未获采用。

## 实施约束与所有权

- 本端 SPI session_id 变化时，所有依赖旧会话的 TCP 控制连接必须关闭；新连接重新发送零会话/序号 HELLO，由已有 HELLO_ACK 报告当前 session_id 和 link_ready。
- TCP HELLO 只读取当前 SPI 状态，不重新分配 SPI 会话。未 ready 不转交控制请求；旧会话不继续执行、导出或重发。
- 会话层输出显式关闭动作，由网络连接的所有者执行关闭；SPI 路径不等待 socket。内部状态变化与关闭动作不能让旧连接在等待关闭期间继续接管旧会话业务。
- 缓存、订阅及导出清理由所属阶段的生命周期实现执行；不回滚 STM32 已应用值、不重放 SET_PARAMS、不新增停车动作。
- 不把关闭连接解释为参数执行失败或未保存；电脑重连后查询请求结果并重新订阅。

## 验证与边界

02/V-6、04/V-7、05/V-5：模拟正常及未 ready 时的会话变化，观察关闭动作、旧连接拒绝接管、重连 HELLO_ACK、SPI 会话不受 TCP HELLO 影响；真实 socket 验证在阶段04/05执行。阶段02只验证会话层动作，不以模拟关闭声明真实 socket 已关闭。

本决定只解除 G-02 的方案选择；G-01、G-03 仍须实施前分别确认。公共协议归档和来源附件保持原文；本文件记录用户确认的实现行为，不宣称电脑端已兼容或三端已核验。
