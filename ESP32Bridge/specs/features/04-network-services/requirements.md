# Phase 04：网络服务 — 需求

> 待实现；规约草案待审查。依据：任务书A/C、协议第1/3/4节、验收5。

## 功能需求

2026-10-18：FR-2按已确认的[g-01-busy](g-01-busy.md)立即HELLO_ACK/BUSY编码；不代表三端已同步。

- **FR-1**：启用WPA2 SoftAP，SSID为`SmartCar-XXXX`，XXXX取AP使用MAC最后两字节的四位大写十六进制；地址192.168.4.1/24、DHCP开启。仅使用合法本地密码，不回退开放热点。网络任务优先级5，网络连接与否不控制SPI启停。
- **FR-2**：监听TCP5000，只保留一个控制会话，第二个连接回复BUSY后关闭且不挤掉第一连接。BUSY遵循G-01确认的SCB/1帧格式，不先发送裸文本或臆造握手前字段。AP关联容量不能代替TCP会话检查，第二连接拒绝必须可验证。
- **FR-3**：按32B头先校验输入长度，再至多接收992B负载；处理任意拆包、粘包、多帧连续输入。每条最大1024B，不随对端输入无限增长缓冲；非法帧关闭连接，不分派部分业务。
- **FR-4**：使用有界等待/可写检查，保留部分发送游标，处理短写、EAGAIN/中断、send返回0、对端关闭和监听端口占用。等待不得越过本端下一个可靠计时截止；不能以socket发送阻塞SPI。普通socket故障回收连接/相关资源，不整机重启。
- **FR-5**：本地处理COMMAND SUBSCRIBE，要求合法当前会话、非零request_id、udp_port为1～65535整数；端口合法则返回对应op/status=OK。目的IP只取当前TCP对端，不接受任意第三方IP；不把SUBSCRIBE转给STM32。非法JSON按坏TCP帧关闭，合法JSON但非法端口返回INVALID_ARG。
- **FR-6**：UDP每报文一帧，只发TELEMETRY、总长≤1016B，端口由订阅决定（电脑默认5001）；无订阅不发送。断线取消订阅、清空该连接的未发遥测；重连必须HELLO并重新订阅，不重放旧设置，不积攒离线记录。
- **FR-7**：TCP HELLO和当前SPI会话状态使用02握手模块；未link_ready不向SPI转交控制请求。会话变化清理旧订阅/待发业务，按[已确认G-02](../02-scb-protocol/g-02-session-change.md)关闭TCP，由重连握手获取新状态，不把TCP连接建立当作SPI重置条件。

## 技术约束

- **TC-1**：TCP只发送头+payload，不含SPI填充；两侧可靠状态独立，UDP独立序号/CRC。网络内存有界，网络任务只持有其自己的缓冲，不能修改驱动持有DMA缓冲。
- **TC-2**：调试打印仅本地串口，业务socket只含SCB/1；不打印密码。UDP目标与当前TCP连接身份绑定，旧连接的延迟工作不得发送给新连接。

## 接口与非目标

输入是网络接口事件、TCP字节流和桥接层待发帧；输出为完整合法帧/连接事件、可靠发送进度或错误。只处理本端网络/订阅，不执行GET_STATUS/SET_PARAMS/日志等STM32业务。G-01/G-02见 [确认门禁](../../research/2026-10-17-baseline-and-decisions.md)。
