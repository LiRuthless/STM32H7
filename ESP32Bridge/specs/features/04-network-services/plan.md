# Phase 04：网络服务 — 实现计划

## 目标与依赖

交付SoftAP、单控制TCP与订阅UDP，依据 [需求](requirements.md) 和 [技术栈](../../techstack.md)。依赖01配置/固定池、02帧/会话；可以模拟SPI，不等待真实车辆。

## 任务分组

### Group 1：热点及连接生命周期

- [ ] 配置WPA2、SSID、地址/DHCP和优先级5网络任务（FR-1）。
- [ ] 控制连接身份、监听失败回收、单控制会话及BUSY拒绝；G-01未确认前不定握手前线格式（FR-2）。

### Group 2：有界TCP流

- [ ] 固定帧接收状态机：读头→验证长度→读负载→完整验证→申请接管。
- [ ] 部分发送游标、可写检查及错误回收，设置有限等待且服务可靠计时（FR-3、FR-4、TC-1）。

### Group 3：订阅和会话

- [ ] 本地SUBSCRIBE、对端IP绑定、UDP发送及断线清理（FR-5、FR-6、TC-2）。
- [ ] 接入HELLO/link_ready、旧会话清理和G-02通知（FR-7）。
- [ ] 按 [验证](validation.md) 注入拆包、慢TCP、第二连接及第三方目标，回填真实结果。

按1→2→3开展，未确认线格式不阻止其他网络和流解析测试。

## 计划模块与追溯

| 需求 | 计划模块 / 职责 | 输入→输出 | 验证 |
|---|---|---|---|
| FR-1 | `main/net_bridge.c/.h`；AP初始化 | 本地配置/MAC→AP、DHCP或报错 | V-1 |
| FR-2 | TCP监听/accept与唯一连接槽 | accept事件→控制身份或BUSY/关闭 | V-2 |
| FR-3 | TCP帧接收状态机 | 分段字节→完整帧或关闭 | V-3 |
| FR-4 | TCP发送游标及事件循环 | 待发帧/可写事件→发送进度/清理 | V-4 |
| FR-5 | 本地订阅分派 | COMMAND/对端地址→订阅和RESULT | V-5 |
| FR-6 | UDP发送与连接清理 | 已订阅遥测/断线→数据报或丢弃 | V-6 |
| FR-7 | 02会话模块与05连接事件接口 | HELLO/链路状态→HELLO_ACK/清理通知 | V-7 |
| TC-1 | 固定接收/发送槽与独立可靠层 | 帧所有权→网络进度 | V-8 |
| TC-2 | 串口日志和连接身份检查 | 调试/旧工作项→串口或拒绝 | V-9 |

所有内部接口传递完整帧和唯一连接身份；容量不足时采用05的接管策略，不让流解析完成自动推进ACK。调用socket的路径只归网络任务；SPI端从固定队列获取已封装帧，不调用socket。

## 风险与取舍

SDK示例的开放回退、密码打印和阻塞回显循环不可复制。TCP的可靠字节流不能替代SCB/1可靠接管语义。第二连接BUSY及换会话通知需三端统一，不把私有字符串夹进协议。网络任务优先级低于SPI只是一项配置，实际不阻塞性仍须故障注入和测量证明。
